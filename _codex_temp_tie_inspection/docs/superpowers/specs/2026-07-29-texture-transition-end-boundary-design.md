# 扎带齿纹结束位置与端头边界定位设计

## 背景与目标

当前实现把“最右白纹相对左右暗部至少亮 40”作为主要条件。用户提供的 `C:\Users\34652\Desktop\20260728\20260728\NG` 文件夹包含 45 张 3072×2048 JPG，其中 38 张图像内容不重复。不同时间和位置的曝光、反光及扎带表面灰度差异较大，同一条末端纹路不一定形成稳定的绝对亮度峰，因此部分扎带在端头预览中显示为橙色“未找到”。

本次目标是把端头左边界从“固定亮度白纹”改为更稳定的“齿纹区结束、光滑端头开始”的结构边界，并确保 NG 文件夹内每张图的所有有效扎带都能生成端头区域。

## 方案比较

### 方案一：降低白纹亮度阈值

优点是改动最小。缺点是弱反光、端头渐变和压缩噪声也会成为候选，容易把端头内部亮度缓变误认为白纹；之前阈值从 20 提高到 40 正是为了解决这种误选，因此不采用。

### 方案二：只做单根扎带的自适应纹理转折

使用每根扎带自身的齿纹能量分布，不依赖绝对亮度。大部分区域可以准确定位，但当 ROI 左边界已经落在光滑段内，或者局部齿纹被反光完全抹平时，单根区域没有足够信息，仍会漏检。

### 方案三：单根纹理定位加同图边界共识补齐

先对每根扎带计算自适应纹理转折并给出置信度，再使用同一张图中高置信结果拟合“边界 X 随 Y 变化”的直线。低置信或未找到的区域由整体边界预测位置，并在附近小范围内做局部边缘细化。该方案既利用单根真实纹理，又利用同批扎带排列规律，不写死绝对坐标，作为本次实现方案。

## 单根纹理转折定位

每根扎带仍使用现有二值掩膜和彩色图同步旋正结果：

1. 在扎带中间 50% 高度内计算逐列灰度中位数，减少上、下轮廓高亮边缘的影响。
2. 对一维列灰度序列计算相邻差分绝对值，并使用按扎带高度归一化的滑动窗口求局部纹理能量。
3. 使用当前扎带自身纹理能量的中位数和中位绝对偏差进行归一化，不使用固定的 `40` 亮度差。
4. 从右向左寻找“左侧持续高纹理、右侧持续低纹理”的最后一个转折。右侧光滑段长度仍要求至少占组件宽度的 35%，并且不少于扎带高度的 2 倍，排除圆头高亮和端头渐变。
5. 在转折附近回查最后一个完整亮纹或最强下降沿，把其右边缘作为端头裁剪起点。
6. 输出边界 X、置信度和定位来源；单根证据不足时不立即失败，交给同图共识阶段处理。

算法只扫描旋正后的局部组件，临时数组按列分配，整体复杂度与 ROI 像素数近似线性。

## 方向统一与有效区域过滤

现场图既可能让扎带朝右，也可能让扎带朝左。每个组件旋正后分别比较左、右内部区间的列纹理能量；若右侧明显更像齿纹区，则把二值和彩色组件同步水平翻转，使光滑圆头始终位于右侧。坐标回映时再撤销翻转，因此界面标注仍落在原图正确位置。

默认 ROI 宽度由图像宽度的 8% 扩大到 16%，避免 ROI 左边界已经越过末端齿纹。连通域提取后使用同图扎带宽度、高度中位数及填充率过滤金属细线、画面边缘残片等伪区域；不按固定像素尺寸或特定序号写分支。

## 同图边界共识

`OpenCvRightEndInspector` 完成全部单根初测后进行第二遍处理：

1. 收集高置信单根边界，并将旋正局部边界中心映射回 ROI 坐标。
2. 使用稳健线性拟合得到 `X = aY + b`，通过中位残差排除误选离群点。
3. 对低置信或未找到的区域，把拟合线映射回该区域的旋正局部坐标，得到预测边界。
4. 在预测位置左右一个扎带高度范围内寻找最近的纹理下降沿；存在可信局部边缘时吸附到边缘，否则直接使用共识预测值。
5. 预测位置必须位于组件内部，并保留至少 3 像素端头宽度；不满足时才标记为未找到。

若整张图没有足够的高置信区域建立共识，则不伪造边界，状态栏明确显示未定位数量。不会使用固定图像坐标，也不会针对某个序号编写分支。

## 接口和结果模型

- 新增 `IRightEndBoundaryLocator`，输入旋正二值和彩色组件，输出带置信度的 `EndBoundaryCandidate`。
- 默认实现为 `TextureTransitionEndBoundaryLocator`，只负责单根纹理分析，不感知其他扎带。
- `OpenCvRightEndInspector` 负责跨区域稳健拟合、低置信补齐、裁剪和坐标逆映射。
- `InspectionRegionResult` 将“白纹”语义改为“端头边界”，增加定位来源：`局部纹理`、`整体补齐` 或 `未找到`。
- WinForms 表格列改为“端头起点 X”“端头裁剪宽度”“定位来源”；端头预览红线继续表示最终裁剪起点，橙线只表示最终仍未找到。
- 所有新增控件或表格列定义继续放在 `MainForm.Designer.cs`，界面文字使用简体中文。

## 批量测试与验收

1. 先使用当前代码遍历 NG 文件夹，记录每张图有效扎带数、局部成功数、失败序号和裁剪宽度，形成可重复失败证据。
2. 从 NG 文件中保留能覆盖“弱纹理”“ROI 左边界已越过末纹”“端头渐变”和“正常强纹理”的最小代表样本到 `samples/NG回归`，避免复制重复图片。
3. 新增单根合成测试：曝光整体变暗或变亮时，齿纹结束位置保持不变。
4. 新增共识补齐测试：多行中部分扎带没有局部纹理时，利用其他高置信行得到有效起点。
5. 新增离群排除测试：一根误选边界不得拉偏其他扎带的预测位置。
6. 新增左右朝向测试：输入朝左组件时，输出必须先统一为圆头朝右再定位。
7. 批量验收覆盖 NG 文件夹全部 45 个文件；重复文件也执行，所有有效连通域必须生成合法端头区域，最终未找到数量为 0。
8. 同时保留原 13 个回归测试，避免新算法破坏此前样图、连通域排序、缩放和平移。
9. Release 构建要求警告 0 个、错误 0 个；最终 WinForms 需通过启动检查。

## 失败处理与性能

- 某根局部定位失败不会中断同图其他扎带。
- 共识样本不足时保留“未找到”，不使用无依据的固定宽度裁剪。
- 批量测试输出每张图的总数、局部定位数、整体补齐数和最终失败数，便于以后增加新现场样本。
- 纹理数组和拟合数据只在一次检测内存在；`Mat`、`Bitmap` 和预览图继续沿用显式释放路径，避免长时间运行累积非托管内存。
