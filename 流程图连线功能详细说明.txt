流程图连线功能独立说明
生成时间：2026-06-11

一、功能目标

连线功能的目标，是让用户可以在画布上把两个模块用一条带方向的线连接起来。

这个功能本身只负责三件事：

1. 用户能从一个模块的连接点拖出一条线。
2. 用户能把这条线连接到另一个模块的连接点。
3. 程序能记录、绘制、选择、删除和恢复这条连接关系。

这里不讨论模块内部怎么运行，也不讨论连接后业务怎么处理。连线功能只提供“谁连接谁、从哪里连到哪里、线怎么显示、用户怎么编辑”。

二、设计思路

1. 连接关系和显示路径分离

连线在界面上是一条折线或曲线，但内部不应该只保存一堆坐标点。

推荐保存的是连接关系：

起点模块。
起点连接点。
终点模块。
终点连接点。
连线类型。
连线编号。

界面需要显示时，再根据起点和终点的位置动态计算线条路径。

这样设计的好处是：

1. 模块移动后，连线会自动跟随。
2. 缩放画布后，连接关系不需要变化。
3. 线条可以重新路由，避开模块或减少交叉。
4. 保存的数据更稳定，不容易因为显示变化影响真实连接。

2. 模块提供固定连接点

每个模块四周可以提供固定连接点，例如：

上连接点。
右连接点。
下连接点。
左连接点。

用户只能从连接点开始拖线，也只能把线连接到连接点上。

这样可以避免线条随意接到模块内部，保证界面清晰、数据可控。

3. 连线是有方向的

连线建议设计成有方向。

一条线至少包含：

从哪个模块出来。
进入哪个模块。

界面上用箭头表达方向。

有方向以后，后续无论是做流程、依赖关系、数据流还是信号流，都可以基于同一套连线数据扩展。

4. 拖线过程只显示预览

用户拖线时，先不要马上创建正式连线。

拖动过程中只显示一条临时预览线。

只有当鼠标松开时，命中了合法目标连接点，才创建正式连线。

这样可以避免产生半条线、空连线或错误连线。

三、基础数据模型

可以把一条连线抽象成 Connection。

字段建议如下：

ID：连线唯一编号。
SourceId：起点模块编号。
SourcePort：起点连接点名称。
TargetId：终点模块编号。
TargetPort：终点连接点名称。
Type：连线类型。
Text：连线备注或标签，可选。

示例：

ID = "c001"
SourceId = "nodeA"
SourcePort = "Right"
TargetId = "nodeB"
TargetPort = "Left"
Type = "Default"
Text = ""

四、连接点模型

连接点可以抽象成 Port。

每个模块可以有多个 Port。

Port 字段建议如下：

Name：连接点名称。
Direction：连接点方向。
Bounds：连接点在画布中的命中区域。
CanOutput：是否允许作为起点。
CanInput：是否允许作为终点。

常见方向：

Top。
Right。
Bottom。
Left。

如果只是简单流程图，可以约定：

左侧连接点一般作为输入。
右侧连接点一般作为输出。
上侧和下侧可根据需要扩展。

五、鼠标触发事件

连线功能主要由三个鼠标事件完成：

1. 鼠标按下

触发条件：
用户在画布上按下鼠标左键。

处理逻辑：

1. 把鼠标屏幕坐标转换成画布坐标。
2. 检查鼠标是否点中了某个模块的连接点。
3. 如果点中了可输出连接点，进入拖线状态。
4. 记录起点模块、起点连接点、起点坐标。
5. 记录当前鼠标坐标，作为临时线终点。
6. 刷新画布，显示临时线。

拖线状态需要保存：

IsConnecting = true。
StartNode。
StartPort。
StartPoint。
CurrentPoint。

2. 鼠标移动

触发条件：
用户按住鼠标并移动。

处理逻辑：

1. 如果不在拖线状态，忽略。
2. 把鼠标坐标转换成画布坐标。
3. 更新 CurrentPoint。
4. 根据 StartPoint 和 CurrentPoint 重新计算临时线路径。
5. 刷新临时线所在区域。

性能建议：

不要每次都刷新整个画布。
只刷新旧临时线区域和新临时线区域。

3. 鼠标松开

触发条件：
用户松开鼠标左键。

处理逻辑：

1. 如果不在拖线状态，忽略。
2. 检查鼠标松开位置是否命中目标连接点。
3. 判断目标连接点是否允许输入。
4. 判断起点和终点是否合法。
5. 判断是否已经存在重复连线。
6. 合法则创建正式 Connection。
7. 清空拖线状态。
8. 刷新画布。

非法情况：

没有命中目标连接点。
目标连接点不允许输入。
起点和终点是同一个连接点。
规则不允许模块连接自己。
已经存在相同连线。
连接类型不匹配。

六、命中检测

1. 连接点命中检测

连接点一般绘制成小圆点或小方块。

命中检测就是判断鼠标点是否落在连接点的矩形区域或圆形区域内。

矩形命中简单，性能也好：

鼠标 X 在连接点 Left 和 Right 之间。
鼠标 Y 在连接点 Top 和 Bottom 之间。

为了让用户容易点中，命中区域可以比视觉图形稍微大一些。

例如视觉圆点直径是 8 像素，命中区域可以扩大到 12 或 14 像素。

2. 连线命中检测

用户点击已有连线时，需要能选中它。

线条本身很细，如果只判断真实线宽，用户很难点中。

推荐做法：

1. 先用连线的外接矩形快速过滤。
2. 再判断鼠标点到线段的距离。
3. 距离小于命中阈值，就认为点中了连线。

命中阈值建议：

普通线宽 1 到 2 像素。
命中范围 6 到 10 像素。

七、连线创建规则

创建连线时建议做以下校验：

1. 起点模块不能为空。
2. 终点模块不能为空。
3. 起点连接点不能为空。
4. 终点连接点不能为空。
5. 起点连接点必须允许输出。
6. 终点连接点必须允许输入。
7. 起点和终点不能完全相同。
8. 如果不允许自连接，则起点模块不能等于终点模块。
9. 如果不允许重复连接，则不能存在相同 SourceId、SourcePort、TargetId、TargetPort 的连线。
10. 如果有连接类型限制，需要检查输出类型和输入类型是否兼容。

八、连线绘制方式

1. 基本绘制步骤

绘制正式连线时：

1. 根据 SourceId 找到起点模块。
2. 根据 SourcePort 找到起点连接点中心坐标。
3. 根据 TargetId 找到终点模块。
4. 根据 TargetPort 找到终点连接点中心坐标。
5. 根据起点和终点计算路径。
6. 绘制路径。
7. 在线尾绘制箭头。
8. 如果有标签，绘制标签。

2. 临时连线绘制

拖线过程中没有正式终点。

临时线的起点是起点连接点中心。
临时线的终点是当前鼠标位置。

临时线建议使用虚线或半透明颜色，表示它还没有正式创建。

3. 选中连线绘制

当一条连线被选中时，建议改变视觉样式：

颜色变亮。
线宽加粗。
显示端点控制点。
显示删除按钮或右键菜单。

这样用户能明确知道当前操作对象是哪条线。

九、线路由

连线路径可以有多种实现方式。

1. 直线

最简单，从起点直接画到终点。

优点：
实现简单。
性能好。

缺点：
容易穿过模块。
复杂流程中线条会比较乱。

2. 折线

常用方式是正交折线。

例如：

从右连接点出来，先水平走一段，再垂直移动，再水平进入目标。

优点：
流程图风格清晰。
箭头方向容易理解。

缺点：
需要处理绕开模块、线段重叠、拐点过多等问题。

3. 贝塞尔曲线

用曲线连接两个点。

优点：
视觉柔和。
实现中等复杂。

缺点：
命中检测和避障稍复杂。
流程图中大量曲线可能影响阅读。

4. 推荐方案

普通流程编辑器建议使用折线。

原因：

1. 方向感强。
2. 容易绘制箭头。
3. 适合表达流程和依赖。
4. 后续可加入避障和缓存优化。

十、路由缓存

如果画布上有大量模块和连线，每次重绘都重新计算路径会影响性能。

可以给正式连线增加路径缓存。

缓存内容：

起点坐标。
终点坐标。
起点连接点。
终点连接点。
路径点集合。
路径外接矩形。

缓存失效条件：

起点模块移动。
终点模块移动。
连接点变化。
连线类型变化。
画布布局规则变化。

不需要缓存的情况：

临时拖线。
模块正在拖动且路径只用于预览。
连线数量很少。

十一、删除连线

删除连线可以有几种入口：

1. 选中连线后按 Delete。
2. 右键连线，点击删除。
3. 选中模块并删除模块时，同时删除相关连线。

删除逻辑：

1. 判断当前是否有选中连线。
2. 从连接集合中移除。
3. 清空选中状态。
4. 清理该连线的路径缓存。
5. 刷新画布。
6. 通知外部连接关系已变化。

十二、撤销和重做

连线新增、删除、移动都建议进入撤销/重做体系。

新增连线操作：

Do：加入 Connection 集合。
Undo：从 Connection 集合移除。

删除连线操作：

Do：从 Connection 集合移除。
Undo：按原位置插回 Connection 集合。

这样用户误删连线后可以恢复。

十三、保存和恢复

连线保存时，只保存连接关系，不保存临时显示状态。

建议保存：

ID。
SourceId。
SourcePort。
TargetId。
TargetPort。
Type。
Text。

不建议保存：

当前是否选中。
临时拖线状态。
当前鼠标位置。
缓存路径。
绘图对象。

恢复时：

1. 先恢复所有模块。
2. 再恢复所有连线。
3. 恢复连线时检查 SourceId 和 TargetId 是否存在。
4. 如果模块不存在，则丢弃无效连线。
5. 恢复完成后重新计算显示路径。

十四、连接关系变化通知

每次新增或删除连线后，建议发出连接变化通知。

通知可以用于：

刷新属性面板。
刷新小地图。
刷新模块连接状态。
触发保存状态变更。
触发合法性检查。

通知不应该直接写死业务逻辑。

推荐只发事件：

ConnectionChanged。

外部谁关心连接变化，谁去订阅这个事件。

十五、常见边界情况

1. 用户从连接点拖出线，但松开到空白处。

处理：
取消临时线，不创建正式连线。

2. 用户拖到同一个模块。

处理：
如果不允许自连接，则取消。
如果允许自连接，则创建自连接线并使用特殊路由。

3. 用户重复连接同一对连接点。

处理：
如果不允许重复，则取消。
如果允许重复，需要给多条线做偏移，避免完全重叠。

4. 用户删除模块。

处理：
同步删除所有以该模块为起点或终点的连线。

5. 用户移动模块。

处理：
模块位置变化后，使相关连线路径缓存失效，并刷新相关区域。

6. 用户缩放画布。

处理：
连接关系不变，只按缩放比例重新绘制。

7. 连线目标模块不存在。

处理：
恢复或绘制时跳过这条无效连线。

十六、建议的内部状态

画布中可以维护以下状态：

Connections：正式连线集合。
SelectedConnection：当前选中的连线。
IsConnecting：是否正在拖线。
ConnectionStartNode：拖线起点模块。
ConnectionStartPort：拖线起点连接点。
ConnectionCurrentPoint：拖线当前鼠标位置。
ConnectionRouteCache：正式连线路径缓存。

十七、实现流程总览

1. 用户按下鼠标。
2. 检查是否命中输出连接点。
3. 命中后进入拖线状态。
4. 用户移动鼠标。
5. 更新临时线终点并重绘临时线。
6. 用户松开鼠标。
7. 检查是否命中输入连接点。
8. 校验连接规则。
9. 创建正式 Connection。
10. 加入 Connections 集合。
11. 清空拖线状态。
12. 刷新画布。
13. 发出连接关系变化通知。

十八、伪代码

鼠标按下：

OnMouseDown(point):
    port = HitTestPort(point)
    if port != null and port.CanOutput:
        IsConnecting = true
        ConnectionStartNode = port.Node
        ConnectionStartPort = port
        ConnectionCurrentPoint = point
        Refresh()

鼠标移动：

OnMouseMove(point):
    if IsConnecting:
        oldBounds = GetTemporaryLineBounds()
        ConnectionCurrentPoint = point
        newBounds = GetTemporaryLineBounds()
        Refresh(oldBounds + newBounds)

鼠标松开：

OnMouseUp(point):
    if not IsConnecting:
        return

    targetPort = HitTestPort(point)
    if targetPort != null and targetPort.CanInput:
        connection = BuildConnection(ConnectionStartPort, targetPort)
        if IsValidConnection(connection):
            AddConnection(connection)

    ClearConnectingState()
    Refresh()

十九、总结

单独看连线功能，它就是一个独立的画布编辑能力。

它不需要知道模块内部业务，也不需要知道连接后要执行什么。

它只需要做好：

连接点命中。
临时拖线。
正式连线创建。
连线路由绘制。
连线选择删除。
连线保存恢复。
连接变化通知。

只要这套能力独立稳定，后续无论外部要把连线解释成流程顺序、数据传递、条件分支还是设备信号，都可以在连线功能之外扩展。
