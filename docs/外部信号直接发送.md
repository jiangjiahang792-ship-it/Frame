# 外部信号直接发送

- Modbus写入、PLC写入、串口发送、相机IO及结果发送均在到达节点后预检并直接调用设备，不进入工件有序队列，也不申请跨节点端点发送权。
- 旧AI信号发送直接调用并等待发送及已配置的保持/复位；TCP客户端等待实际发送，配置等待响应时继续等待响应。TCP服务器、手动相机IO、IO卡和光源原本没有接入工件有序队列，保持各自直接调用方式。
- 不新增发送锁；串口驱动已有的单次写入保护和通信SDK内部同步保留。直接发送不是硬实时承诺，仍可能耗时于设备响应、SDK同步和操作系统调度。
- 相机IO保留“是否异步”：关闭时等完整脉冲结束，开启时直接发起脉冲后继续后续节点，日志区分“已发起”和“脉冲完成”。已有工件上下文时仅登记在途生命周期，工件/运行会话结束仍等待脉冲退出，不用来安排不同工件或设备的发送顺序。无工件上下文也可以直接发送。
- 发送开始前响应取消；相机脉冲已经开始后继续尝试复位，防止因停止而遗留高电平。发送失败不自动重试、不回放历史结果。
- 不保证跨流程、跨工件的发送顺序或整批独占。多个调用操作同一地址可能覆盖；同一相机的线路选择和电平API也可能交错，重叠脉冲可能合并或被提前拉低。复位前重新选择本次线路不能提供原子性，需要现场避免并发操作同一物理输出。
- API或协议成功不等于PLC业务程序已处理。需要业务确认时使用接收端握手，不能从节点成功日志推断现场动作已完成。
- 相机帧缓存、单流程FIFO和流程组调度未改，不属于本次删除的发送排队。

验证：`Tests/ExternalSignalDirect.Tests.ps1`，旧串口/PLC/相机IO专项脚本名保留为兼容入口。只使用假设备和本机服务，不连接现场硬件。
