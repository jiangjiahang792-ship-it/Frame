# 订阅结果数据分类与输入输出契约设计

日期：2026-07-22

## 1. 目标

当前订阅系统主要依据结果属性的 CLR 类型和 `DisplayName` 反射生成候选项，但不同调用方没有统一声明自己需要的数据类型，因此候选结果太多、类型校验方式也不一致。

本设计中的“分类”首先是数据类型分类，不是业务来源限制。`bool` 就是布尔类型，不再额外划分“判定类型”；Modbus 读取到的 `short` 就是数值类型，不会因为数据来自通信节点而禁止四则运算、多条件、写入等数值输入直接订阅。

本次改造把订阅关系统一定义为“输出端口与输入端口的契约连接”：

1. 每个可订阅输出明确声明数据类别、实际 CLR 类型、数量形态和显示级别。
2. 每个订阅输入明确声明允许接收的数据类别、CLR 类型和数量形态。
3. 候选列表生成、点击确认和运行取值统一调用同一个兼容性校验服务。
4. “核心、高级、隐藏”只控制界面展示，不再承担类型兼容判断。
5. 不删除现有结果属性和算法逻辑，不改变旧方案保存的节点名称与属性路径。

## 2. 三个相互独立的维度

### 2.1 数据类别

数据类别回答“这份值能作为哪类输入使用”。首版统一定义以下类别：

| 大类 | 数据类别 | 典型内容 |
|---|---|---|
| 基础 | 布尔 | `bool`，包括 OK/NG、是否找到、条件结果和普通开关量 |
| 基础 | 数值 | `byte`、`short`、`ushort`、`int`、`uint`、`long`、`ulong`、`float`、`double`、`decimal` 等数值 |
| 基础 | 文本 | 二维码、通信文本、提示信息 |
| 图像 | 图像 | `OutputImage` |
| 几何 | 点 | 单个二维点 |
| 几何 | 点集合 | 边缘点、采样点等无闭合语义的点集 |
| 几何 | 轮廓 | 具有轮廓语义的有序点集 |
| 几何 | 直线 | 起终点或直线模型 |
| 几何 | 圆 | 圆心和半径组成的圆模型 |
| 几何 | 椭圆 | 中心、长短轴和角度组成的椭圆模型 |
| 几何 | 矩形 | 普通矩形或旋转矩形 |
| 几何 | 区域 | 多边形或封闭检测区域 |
| 定位 | 位姿 | X、Y、角度、ScaleX、ScaleY 组成的目标位姿 |
| 定位 | 位置修正 | 基准位姿到当前位姿的修正信息 |
| 复合 | 算法绘制结果 | `AlgorithmResult` 等供绘制、汇总使用的完整对象 |
| 复合 | 测量结果 | 卡尺和距离工具的单目标或多目标结构化结果 |
| 结构 | 结构化对象 | PLC 批量结果、Modbus 批量结果、TCP 对象、共享变量对象等不能拆成基础值的对象 |
| 兼容 | 旧版对象 | 暂时无法明确分类的历史 `object` 输出，只用于兼容和高级显示 |

基础值只按实际数据类型归类，不按节点来源归类：相同的 `short` 无论来自 Modbus、PLC、四则运算还是测量结果，都是“数值”。“点”和“位姿”仍要分开：点只有坐标，位姿还包含角度和缩放。“点集合”“轮廓”“区域”即使 CLR 类型相同，也必须通过数据类别区分，避免复杂视觉对象误接。

### 2.2 数量形态

数量形态回答“有几个”：

- 单值：一个数值、一个点、一个圆、一个位姿。
- 集合：同一语义的一组数据，例如点集合、轮廓集合。
- 多目标结果：与模板匹配目标一一对应的结果集合，必须保留目标顺序和失败占位。

多目标结果不能自动降级成单值，除非输入端口明确声明允许“取第一目标”。这样可避免下游无意中丢失第 2 个及后续目标。

### 2.3 显示级别

显示级别回答“普通用户是否默认看见”：

- 核心：默认显示，例如布尔值、主要数值和动态变量。
- 高级：默认收起，例如图像、轮廓、点集、多目标结构化结果和算法绘制结果；当输入端口明确需要该类别时自动显示。
- 隐藏：不允许新建普通订阅，但旧方案原路径继续解析。

因此，显示级别不会改变数据兼容性；一个高级图像输出仍然是合法图像输入。

## 3. 统一模型

新增统一端口模型，名称可在实施时按现有命名空间调整：

- `SubscriptionDataCategory`：数据类别枚举。
- `SubscriptionValueMultiplicity`：单值、集合、多目标结果枚举。
- `SubscriptionOutputVisibility`：核心、高级、隐藏枚举。
- `SubscriptionOutputAttribute`：静态结果属性的输出声明。
- `SubscriptionOutputDescriptor`：统一输出描述，包含节点、路径、显示名、数据类别、CLR 类型、数量形态、显示级别和是否动态。
- `SubscriptionInputContract`：输入契约，包含允许的数据类别、允许的 CLR 类型、允许数量形态和数值转换策略。
- `ISubscriptionOutputProvider`：静态和动态输出的统一提供接口。
- `SubscriptionPortCatalog`：集中发现、缓存和查询全部输出端口。
- `SubscriptionCompatibilityService`：唯一的输入输出兼容性校验入口。

静态输出通过属性显式标注；动态输出由现有动态变量提供器返回完整描述符。任何新结果属性如果没有端口声明，默认不可新建订阅，从制度上防止结果列表再次失控。

## 4. 兼容性校验顺序

一次订阅必须依次通过以下检查：

1. 输出仍然存在，动态变量未被删除或改名。
2. 输出数据类别属于输入允许类别。
3. 输出数量形态属于输入允许形态。
4. 输出 CLR 类型能够赋给输入类型，或存在已登记的安全转换。
5. 节点作用域合法，例如组合模块内部端口不能泄露到外部。

基础数值采用统一转换矩阵，不因为 CLR 数值类型不同就直接拒绝订阅：

- `short` 输出可直接订阅到接受数值的四则运算、多条件、通信写入等输入。
- 安全扩宽转换直接允许，例如 `short` 到 `int`、`long`、`float`、`double` 或 `decimal`。
- 可能溢出或损失小数的缩窄转换，只有输入端口明确允许时才显示，并在运行取值时进行范围检查。
- 布尔只属于布尔类型；需要把 0/1 当布尔时，由具体输入显式开启转换，不能把所有数值默认当作布尔。
- 文本与数值之间不做全局隐式转换；需要通信格式化时由对应节点明确开启。
- 点集合不能仅因底层是 `List<PointF>` 就自动转换为轮廓或区域。
- `object` 不能作为“什么都能接”的通配类型，只能走旧版兼容或调用方明确允许的通信对象输入。

候选列表只展示能够直接使用或能够通过已允许数值转换使用的输出；点击确认时再次校验；`GetValue<T>` 运行取值时做最后校验并输出明确中文错误，不能以无效强制转换异常结束。正常的数值兼容订阅不会弹出错误。

## 5. 输入端口声明示例

- 图像处理和测量工具的图像输入：只接受“图像 + 单值 + `OutputImage`”。
- 位置修正输入：只接受“位姿 + 多目标结果 + 模板位姿列表的实际类型”。
- 卡尺等测量工具的位置修正输入：只接受“位置修正 + 多目标结果 + `List<PositionCorrectionInfo>`”。
- 线组合拟合输入：接受“点集合”或明确登记的“轮廓”，不接受普通区域。
- 四则运算输入：接受“数值 + 单值”，包括 Modbus 的 `short`、PLC 的整数和测量节点的浮点数。
- 多条件输入：接受“布尔、数值、文本 + 单值”，不直接接受图像和结构化测量结果。
- 结果绘制输入：接受“图像”和“算法绘制结果”，两个输入端口分别声明，不能混用。
- 组合模块端口：新建端口时保存数据类别、CLR 类型和数量形态；旧端口按已有 CLR 类型推断并标记为“兼容推断”。

## 6. 动态变量

四则运算、Modbus 读取、组合输入、组合输出和组合模块继续使用动态变量，但必须进入同一目录：

1. 四则运算变量归类为“数值 + 单值”。
2. Modbus 单地址变量按实际 CLR 类型归类：线圈量为“布尔”，`short`、`ushort`、`int`、`float` 等为“数值”；批量读取对象才归类为“结构化对象”。
3. 组合端口的新配置显式保存数据类别、类型和数量形态。
4. 旧组合端口先依据现有 CLR 类型作兼容推断，不强制修改方案文件；用户下次编辑端口时可明确类别。
5. 动态变量删除或改名后立即触发目录刷新，旧订阅显示“结果不存在”，不能自动切换到第一项。

## 7. 界面行为

1. 普通订阅列表只显示与当前输入契约兼容的结果。
2. 候选项显示统一类别前缀，例如“[图像] 输出图像”“[位置修正·多目标] 位置修正信息”。
3. 通用订阅结果下拉框提供右键勾选项“显示高级结果”，默认关闭；该菜单组件必须放在 `.Designer.cs` 中，`Text` 使用中文。采用右键菜单是因为现有订阅控件中有大量 32 像素固定高度实例，增加第三行会破坏既有参数窗体布局。
4. 当输入端口只接受图像、轮廓、位置修正等高级类别时，匹配结果自动显示，不要求用户额外勾选高级结果。
5. 已保存的隐藏属性继续显示为“兼容订阅”；已删除属性显示为“结果不存在”。两者都不能静默改选。
6. 类型不兼容时，界面直接给出“输入需要什么、当前输出是什么”的中文提示；兼容数值类型直接允许订阅。

## 8. 与现有结果审计的关系

`docs/订阅节点结果审计与保留建议-2026-07-22.md` 的初次审计记录为 229 个静态输出；实施前按当前源代码重新扫描为 230 个。核心、高级、隐藏建议继续有效，并为每项补充数据类别和数量形态。

实施时先建立一份机器可检查的完整映射：

- 所有带 `DisplayName` 的可订阅属性必须同时具有输出端口声明。
- 任何未分类属性都使完整性测试失败。
- 动态提供器的每个变量必须返回非空类别和实际类型。
- 同一个属性路径不能注册成两个冲突类别。

## 9. 旧方案兼容

1. 不改变现有节点名称、属性名、`DisplayName` 和订阅路径序列化格式。
2. 隐藏输出只禁止新选，旧路径继续读值。
3. 旧方案原本 CLR 类型可用但缺少分类信息时，允许一次兼容推断并记录诊断；保存新配置后写入明确契约。
4. 真正 CLR 类型不兼容的旧订阅不能静默转换或切换，必须显示错误并要求用户重选。
5. 位置修正的单目标兼容属性继续存在，但新的多目标测量输入只接受多目标位置修正端口。

## 10. 性能

1. 静态属性反射只在首次遇到结果类型时执行，描述符按类型缓存。
2. 兼容矩阵和输入契约预计算，运行时不重复扫描程序集。
3. 动态变量仅在节点输出定义变化事件触发时刷新，不在每帧运行中重建。
4. 运行取值使用已选描述符和已缓存访问器，避免每次按显示名全量反射。

## 11. 测试要求

1. 分类完整性：当前 230 个静态输出全部显式分类，新增未分类输出会导致测试失败。
2. 兼容矩阵：覆盖图像、点、点集合、轮廓、区域、位姿、位置修正、数值、布尔和文本的正反例。
3. 数值直订：验证 Modbus `short` 可直接用于四则运算、多条件和允许数值的通信输入，不出现订阅类型错误。
4. 同 CLR 不同类别：验证 `List<PointF>` 的点集合不能错误接入仅接受轮廓或区域的输入。
5. 数量形态：多目标结果不能误接单值端口，允许取第一目标时必须显式配置。
6. 动态变量：新增、删除、改名后候选项立即刷新。
7. 旧方案：隐藏路径继续工作，不存在路径不自动跳项，不兼容路径给出中文错误。
8. 界面：高级结果默认收起，精确类型输入自动显示所需高级类别。
9. 性能：目录缓存后每帧运行不发生全量结果属性扫描。

## 12. 实施顺序

1. 先建立数据类别枚举、端口描述符、目录和兼容性服务，并用测试固定兼容矩阵。
2. 为全部静态结果和动态变量补齐输出声明。
3. 为全部 `NodeSubscription` 使用点补齐输入契约，保留旧 `SetExpectedValueType<T>` 作为过渡适配器。
4. 改造普通订阅和多条件、四则运算、组合模块等自定义选择器，共用统一目录。
5. 加入高级结果界面、旧方案兼容显示和中文错误提示。
6. 完成全量构建、结构测试、典型方案回归和任务记录。

本设计不在首版引入并发，也不改变测量算法执行方式；只治理订阅端口、显示和校验。
