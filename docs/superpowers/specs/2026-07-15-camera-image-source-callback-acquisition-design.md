# 相机图像源统一回调取图设计

## 1. 背景

当前相机图像源存在两条取图路径：

- 普通流程运行到 `NodeImageSource` 时调用 `GetOneFrameImage()` 同步取图。
- 勾选“是否为相机回调触发流程”后，由相机帧回调保存图像，再从图像源下游启动另一轮流程。

两条路径使软触发、硬触发、单次运行、循环运行和停止操作具有不同语义。新的设计统一使用相机回调接收图像，不再通过 `GetOneFrameImage()` 获取相机帧，同时保证软触发时图像源上游节点先运行。

## 2. 已确认目标

1. 相机图像源统一使用回调取得图像。
2. 软触发流程先运行上游节点；运行到图像源后调用一次 `GrabOne()`。
3. 回调帧唤醒当前正在等待的 `NodeImageSource`，由同一次 `Process.Run` 和同一个 `RunId` 继续运行下游。
4. 回调不再重新调用 `Process.Run()`。
5. 相机图像源不再调用 `GetOneFrameImage()`，也不设置同步取图回退路径。
6. 硬触发图像源存在上游节点时属于非法流程配置，所有用户运行入口必须在启动前弹出中文提示并拒绝运行对应流程。
7. 点击停止后必须取消回调等待、停止本次运行启动的相机取流，并丢弃迟到帧。
8. 取消 `Off` 触发模式的界面设置，所有相机图像源固定使用 `TriggerModel.On`。
9. 旧方案中的 `TriggerModel.Off` 加载后自动迁移为 `On`，保留原有触发源并记录提示日志。

## 3. 方案比较

### 3.1 采用：同一轮流程等待回调

流程线程运行到图像源后先登记本轮回调等待，再根据触发源发送软触发或等待硬触发。回调只交付图像并唤醒等待者，节点随后在原流程中完成并继续调度下游。

优点：上游结果、节点状态、运行统计和 `RunId` 完整一致；停止操作可以通过现有取消令牌贯穿整轮流程；不会与 `Process.IsRuning` 冲突。

### 3.2 不采用：回调重新启动流程

流程运行到图像源后发送触发并退出，回调再调用 `Process.Run(nodeImage, false)`。

缺点：一次业务运行被拆成两个 `RunId`；上游结果可能被新批次清空；回调到达时流程可能仍处于运行状态而被拒绝；停止和统计语义不稳定。

### 3.3 不采用：全局循环统一发送软触发

由 `Solution` 的循环任务直接调用相机软触发，回调后从图像源向下执行。

缺点：无法保证每次采图前运行图像源上游节点；与本次明确需求冲突。

## 4. 总体架构

### 4.1 回调等待协调器

将“登记一次等待、提交一帧、取消等待、拒绝迟到帧”抽象为 `ICameraFrameAwaiter` 接口和默认 `CameraFrameAwaiter` 实现，供 `NodeImageSource` 使用。协调器必须满足：

- 每个图像源同一时间最多存在一个有效等待者。
- 登记等待发生在 `GrabOne()` 之前，避免高速回调先于等待状态建立。
- 回调帧只能完成当前等待批次，已经取消或已经完成的批次不得接收迟到帧。
- `Mat` 的所有权必须明确转移；未被接收的帧立即释放。
- 停止和节点释放时必须取消等待并释放持有图像。
- 状态切换使用轻量同步原语，不在相机回调线程执行算法或阻塞等待。

接口负责协作契约，默认实现负责线程安全，便于后续替换为带队列、帧号匹配或相机厂商时间戳匹配的实现。

### 4.2 运行配置校验器

将相机流程运行前检查抽象为 `IProcessCameraConfigurationValidator` 接口和默认 `ProcessCameraConfigurationValidator` 实现。校验器遍历待运行流程中的有效图像源节点，并检查：

- 图像源类型是否为“相机”。
- 触发源是否为 `LINE0`～`LINE4`。
- 当前图像源是否存在沿流程连线可达的上游节点。

发现非法配置时返回结构化中文错误，不在校验器内部直接显示窗体。流程编辑页、主窗体单次运行和主窗体循环运行统一调用校验器并负责弹窗。底层运行入口保留无界面安全检查和日志，避免其他调用路径绕过规则。

“存在上游节点”按流程方向定义：画布流程递归检查指向图像源的入边；节点在画布上的视觉位置不参与判断。没有连线的旧流程按节点列表顺序判断，排在图像源之前的有效节点视为上游节点。

## 5. 运行数据流

### 5.1 软触发

1. 流程从正常起始节点运行，上游节点按既有顺序或并行规则执行。
2. `NodeImageSource.Run()` 检查相机、参数和取消令牌。
3. 节点确保回调订阅与相机取流处于可用状态。
4. 节点为当前运行登记一次回调等待。
5. 节点调用 `camera.GrabOne()`，只发送一次软触发命令。
6. 相机回调把图像提交给当前等待者并立即返回。
7. 节点收到图像后构建 `NodeResultImageSource.OutputImage`，写入成功状态。
8. 节点返回 `ContinueRun`，同一轮流程继续调度下游节点。

当前 `Solution.TriggerSoftCameraCallbacksForProcesses()` 不再参与正常循环运行，避免图像源和全局循环重复发送软触发。

### 5.2 硬触发

硬触发图像源必须没有上游节点。合法流程启动后：

1. 流程进入图像源节点，建立回调等待并确保相机取流已经启动。
2. 节点不调用 `GrabOne()`，等待外部线路触发回调或用户停止。
3. 单次运行收到一帧后完成图像源及下游一次运行，然后停止本次启动的取流。
4. 循环运行收到一帧后完成下游一次运行，再进入下一轮等待，直到用户停止。

### 5.3 非相机图像源

本地图像和共享变量继续使用现有同步节点逻辑，不经过相机回调等待协调器。

## 6. 界面与配置

### 6.1 流程菜单

从 `ProcessEditPanel.Designer.cs` 的流程菜单中移除“是否为相机回调触发流程”。`ProcessConfig.IsCameraCallbackTriggered` 和 `Process.IsCameraCallbackTriggered` 本次保留用于旧方案反序列化兼容，但运行时不再读取它们决定相机取图路径；新方案无论该兼容字段取值如何都使用统一回调语义。

### 6.2 图像源参数界面

- 在 `ParamFormImageSource.Designer.cs` 中移除“触发模式”标签和 `Off/On` 下拉框，并回收对应布局空间。
- “触发方式”继续显示“软触发、Line0～Line4”。
- 保存相机参数时始终写入 `TriggerModel.On`。
- 所有控件和布局变更都在 `.Designer.cs` 中完成，保证 WinForm 设计器可见。

### 6.3 旧方案迁移

加载图像源参数时，如果发现 `TriggerModel.Off`：

1. 在内存中改为 `TriggerModel.On`。
2. 保留原 `TriggerSource`；无法识别的触发源按既有兼容规则转换为软触发。
3. 写入一条中文提示日志，包含流程名和图像源节点名。
4. 不立即改写方案文件；用户下次保存时写回新值。

## 7. 停止、异常与并发

### 7.1 停止

点击停止后按以下顺序处理：

1. 取消方案或流程运行令牌。
2. 取消所有正在等待的图像源回调任务。
3. 停止本次运行实际启动的相机取流，不停止原本已由其他功能启动的相机。
4. 清理尚未消费的回调图像和等待状态。
5. 回调晚于取消到达时立即释放图像，不重新启动流程。

### 7.2 异常

- 相机无效、未打开、回调订阅失败、开始取流失败或 `GrabOne()` 抛出异常时，图像源节点失败并停止当前分支。
- 成功发送 `GrabOne()` 后只等待对应回调或用户停止，不调用 `GetOneFrameImage()` 回退。
- 硬触发等待允许持续到外部触发或用户停止。
- 异常日志使用简体中文并包含流程、节点、相机和当前 `RunId`。

### 7.3 性能

- 相机回调线程只做帧校验、所有权转移和等待者唤醒。
- 图像转换、结果构建和下游算法继续在流程运行线程执行。
- 不在回调线程调用 `Process.Run()`，减少线程创建、上下文切换和重入竞争。
- 不建立无界帧队列；一个等待周期只消费一帧，额外帧立即释放。

## 8. 运行入口校验与提示

以下入口必须在开始相机取流和设置运行态之前执行相同校验：

- 流程编辑页单次运行。
- 流程编辑页循环运行。
- 主窗体方案单次运行。
- 主窗体方案循环运行。

弹窗按流程汇总非法节点，中文信息应明确指出：流程名称、图像源节点名称、硬触发源，以及“硬触发图像源不能存在上游节点”。存在多个错误时一次性展示，避免连续弹出多个消息框。

## 9. 测试与验收

### 9.1 自动化检查

1. 相机图像源运行路径不再调用 `GetOneFrameImage()`。
2. 软触发在登记等待后只调用一次 `GrabOne()`。
3. 回调完成后上下游属于同一个 `RunId`。
4. 回调期间不调用新的 `Process.Run()`。
5. 硬触发存在上游时，四个用户运行入口均拒绝启动并返回中文错误。
6. 硬触发没有上游时，单次运行消费一帧，循环运行可消费多轮。
7. 点击停止能够取消软触发和硬触发等待，并停止本次启动的相机。
8. 停止后的迟到帧被释放，不更新节点结果。
9. `Off` 旧参数迁移为 `On`，触发源保持不变。
10. 参数界面不再显示 `Off/On` 控件，触发方式控件仍可正常配置。

### 9.2 验收场景

- `上游节点 → 软触发图像源 → 检测节点`：每轮先完成上游，再软触发一次，回调后继续检测。
- `硬触发图像源 → 检测节点`：单次运行等待一次外部触发；循环运行持续响应外部触发；停止后不再响应。
- `上游节点 → 硬触发图像源`：运行前弹窗并拒绝启动。
- 加载旧 `Off` 方案：界面不显示 `Off`，运行参数为 `On`，原触发源保持一致。

## 10. 范围边界

本次只统一二维相机 `NodeImageSource` 的回调取图链路，不修改本地图像、共享变量和三维图像源的运行方式，不重构相机厂商 SDK 实现，也不引入多帧缓存或掉帧补偿策略。
