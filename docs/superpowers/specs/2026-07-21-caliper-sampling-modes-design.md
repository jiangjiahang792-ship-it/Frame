# 卡尺快速采样与抗干扰采样双模式设计

## 背景

当前公共卡尺算法为了增强金属反光和单像素毛刺环境下的稳定性，对每个扫描剖面位置沿卡尺宽度进行多点灰度平均，并对每个采样点执行双线性插值。该方式提高了抗干扰能力，但使单目标卡尺找线、找圆和找椭圆的运行时间相较旧版明显增加。

日志与代码对比已经确认：单目标执行路径没有进入 `Parallel.For`，性能回退来自公共卡尺算法的宽度平均与双线性采样，不是多目标并发调度造成的。

## 目标

- 卡尺找线、卡尺找圆和卡尺找椭圆均支持“快速采样”和“抗干扰采样”。
- 默认使用快速采样，使普通场景的单目标性能接近旧版。
- 抗干扰采样保留当前宽度平均和双线性插值行为，不降低现有复杂场景的稳定性。
- 旧 `.Sol` 方案缺少新增字段时自动使用快速采样，无需用户重新配置。
- 三个参数窗体均可独立选择采样模式，控件必须位于对应 `.Designer.cs` 文件中。

## 方案选择

采用每个卡尺节点独立保存枚举模式的方案，不使用全局配置，也不使用只能表达两种状态的布尔字段。

新增公共枚举：

```csharp
public enum CaliperSamplingMode
{
    Fast = 0,
    AntiInterference = 1
}
```

`Fast` 固定为零值。Newtonsoft.Json 反序列化旧方案时，缺少枚举属性将保留类型默认值 `0`，因此旧方案自动进入快速采样。

## 参数与界面

以下节点参数增加 `SamplingMode` 属性，默认值为 `CaliperSamplingMode.Fast`：

- `NodeParamCaliperLine`
- `NodeParamCaliperCircle`
- `NodeParamCaliperEllipse`

公共算法参数同步增加该属性：

- `CaliperLineParams`
- `CaliperCircleParams`
- `CaliperEllipseParams`

三个参数窗体的卡尺参数区域增加：

- 中文标签：`采样模式`
- 下拉选项：`快速采样`、`抗干扰采样`
- 默认选择：`快速采样`

界面使用中文显示文本与枚举值之间的明确映射，不依赖枚举英文名称直接显示。加载参数时根据枚举选择下拉项，保存参数时根据下拉项写回枚举。

## 算法数据流

卡尺找线、找圆和找椭圆继续复用 `CaliperMeasurementAlgorithm`。每个节点把自己的 `SamplingMode` 从节点参数传入公共算法参数。

公共边缘剖面函数根据采样模式选择路径：

### 快速采样

- 沿扫描方向逐点计算像素坐标。
- 使用旧版最近邻取整方式读取中心线上的单个灰度像素。
- 保留现有平滑、梯度、极性、查找模式和拟合逻辑。
- 不执行宽度方向循环和双线性插值。

### 抗干扰采样

- 保留当前沿卡尺宽度的多点采样。
- 保留当前双线性插值。
- 保留当前最大半宽限制、越界处理和灰度平均行为。
- 输出行为与当前版本保持一致。

采样模式只改变一维灰度剖面的生成方式，不改变位置修正、ROI 仿射变换、多目标结果顺序、单目标失败隔离和节点总体状态。

## 其他测量工具的行为

点点距离、点线距离、点区域距离等工具内部也会构造公共卡尺算法参数。它们当前没有独立采样模式控件，因此未显式赋值时使用枚举零值 `Fast`。本次不扩大这些工具的界面范围；如果后续需要逐工具控制，可以复用同一个枚举和界面映射。

## 错误与兼容处理

- 未知枚举值统一回落到快速采样，避免损坏方案导致算法进入不可预测分支。
- 旧方案缺少 `SamplingMode` 字段时使用快速采样。
- 保存后的新方案明确写入所选模式。
- 切换采样模式不改变已有 ROI、卡尺数量、阈值、极性、查找方式和位置修正订阅。

## 测试设计

新增专项 PowerShell 契约测试，按测试驱动方式先观察失败，再实现功能：

- 公共枚举存在，且 `Fast` 等于零。
- 三类节点参数和三类公共算法参数均具有 `SamplingMode`，默认值为快速采样。
- 三个参数窗体在 `.Designer.cs` 中包含“采样模式”标签和下拉框。
- 三个窗体完成参数加载、保存和算法参数传递。
- 快速采样路径使用单中心线像素读取，不进入宽度平均函数。
- 抗干扰采样路径继续调用宽度平均和双线性采样。
- 未知枚举值回落到快速采样。
- 既有多目标卡尺和位置修正专项测试继续通过。
