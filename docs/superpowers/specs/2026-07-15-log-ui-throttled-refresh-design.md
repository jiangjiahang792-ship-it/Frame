# 日志界面限频批量刷新设计

## 背景与根因

当前日志写文件与界面显示共用日志入口。文件写入已经在后台队列串行执行，但界面显示在软件非运行状态下仍然为每条日志单独调用一次 `BeginInvoke`，随后分别更新“全部”列表和等级列表，并重复切换选中项触发滚动与重绘。

当日志产生速度超过 UI 线程处理速度时，Windows 消息队列会持续堆积日志刷新委托，鼠标、菜单和按钮消息得不到及时处理。软件运行结束后，现有逻辑还可能一次性排空最多 1000 条待显示日志，造成第二次长时间占用 UI 线程。

## 目标

- 日志文件继续完整记录，不因界面限流丢失文件日志。
- 高频日志不能通过逐条 UI 调度占满界面线程。
- 日志界面可见时保持近实时显示，正常情况下刷新延迟不超过约 100ms。
- 高负载时优先显示最新日志，允许仅在界面显示层淘汰较旧记录。
- 日志窗口隐藏时不执行无意义的列表重绘。
- 保持日志等级筛选、清空显示、打开日志目录等现有功能。

## 方案

采用“有界缓冲区 + WinForms 定时器 + 限量批处理”方案。

日志后台工作线程完成文件写入后，只把需要显示的轻量日志条目放入界面缓冲区，不再逐条调用 `BeginInvoke`。`LogHelper` 使用设计器中的 WinForms 定时器，每 100ms 在 UI 线程执行一次刷新；每次最多取出 100 条，保证单次处理时间有上限，并给鼠标、按钮和绘制消息留下处理机会。

界面缓冲区默认最多保留 2000 条。达到上限后淘汰最旧条目，保留最新日志。此限制只影响界面显示，不影响已经写入日志文件的内容。

## 组件设计

### 日志界面缓冲区

新增可替换接口，职责仅包括：

- 快速写入一条待显示日志；
- 按指定最大数量批量取出日志；
- 返回当前待处理数量；
- 清空待显示日志。

默认实现使用线程安全队列和独立计数，避免在高频路径反复扫描队列。写入超过容量时从队首淘汰旧日志，保证内存有界。

### LogHelper 调度

- 删除按 `Solution.IsRunning` 决定是否逐条刷新的分支，所有运行状态统一走缓冲区。
- 删除每条日志对应一次 `BeginInvoke` 的路径。
- 在 `LogHelper.Designer.cs` 中添加 100ms 的 `Timer` 组件，保证设计器可以看到组件配置。
- 定时器仅在控件可用且日志窗口可见时取出一批日志。
- 隐藏期间缓冲区继续保留最新 2000 条，不更新列表控件。

### 列表批量更新

一次刷新涉及的列表统一调用 `BeginUpdate`，批量添加完成后再调用 `EndUpdate`。

- “全部”列表最多保留 1000 条；
- 各等级列表最多保留 300 条；
- 超限时删除最旧的超出部分，不再清空整张列表；
- 每批处理结束后只滚动一次当前可见列表，不再为每条日志切换两次选中项。

`EndUpdate` 放在 `finally` 中，避免单条异常导致控件长期停止重绘。

## 数据流

1. 任意线程调用 `LogHelper.AddLog`。
2. 后台日志工作线程完整写入日志文件。
3. 需要显示的日志进入有界界面缓冲区。
4. UI 定时器每 100ms 检查日志窗口状态。
5. 窗口可见时最多取出 100 条并批量更新对应列表。
6. 如果仍有积压，后续定时器节拍继续处理，UI 线程不会一次性排空全部日志。

## 异常与生命周期

- 控件已释放或句柄尚未创建时不刷新 UI，避免关闭过程出现跨线程异常。
- 定时器随 `components` 一起释放，不保留静态 UI 定时器。
- 日志事件在 `LogHelper` 释放时解除订阅，避免旧日志窗口实例被静态事件持有。
- 单条列表更新异常不能影响日志文件后台写入，也不能阻断下一批刷新。

## 测试

- 缓冲区容量测试：持续写入超过 2000 条后数量保持有界，并保留最新条目。
- 批量取出测试：每次最多返回指定数量，剩余条目留待下一批。
- 并发测试：多个生产线程写入时不抛异常且容量不失控。
- 静态架构检查：日志事件中不存在逐条 `BeginInvoke`，定时器位于 `.Designer.cs`，批量大小和列表上限明确。
- 运行现有日志等级、诊断日志和资源释放回归测试。
- 执行 `Debug|x64` 完整编译。

## 不在本次范围

- 不改变日志文件格式、目录、保留容量和等级过滤规则。
- 不增加新的用户配置界面。
- 不修改业务节点的日志内容和日志调用频率。
