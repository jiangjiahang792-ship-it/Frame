# 大模型节点保存时预加载设计

## 背景

大模型节点当前在选择模板时完整解包一次，在第一次流程运行时又完整解包并初始化 native 模型。TensorRT/CUDA 初始化和第一次推理的延迟因此落在生产流程首帧，且预览缓存与推理缓存重复占用磁盘。

## 已确认目标

- 选择模板时只读取 `manifest.json`，不解包 Engine、ONNX 或 Bank。
- 点击“保存”后在后台线程完成模板解包、native 模型初始化和一次空图预热。
- 保存成功后关闭参数窗口；加载失败时保留窗口和原来可用模型，并显示简体中文原因。
- 运行阶段使用已经加载的模型，只执行图像准备和 native 推理。
- 图像阈值、面积阈值和最大框数是单次推理参数，修改它们不重新加载模型。
- 从旧方案直接恢复且尚未点击保存的节点，保留运行时兜底加载，避免已有方案无法运行。

## 方案比较

1. 保持运行时首次加载：改动最少，但首帧仍然很慢，不能满足目标。
2. 保存按钮同步加载：可以把耗时移出运行阶段，但会冻结参数窗口。
3. 保存时异步预加载并原子替换：界面保持响应，预热完成后运行只走推理；新模型失败时旧模型仍可继续使用。本次采用此方案。

## 详细设计

### 模板信息读取

`LargeModelTemplatePackage` 新增公开的清单读取方法。它直接打开 `.tdlarge` 压缩包并反序列化 `manifest.json`，不创建 `_LargeModelPreview` 目录，也不读取模型和 Bank 大文件。

### 模型预加载

`LargeModelDetectionRuntime` 提供预加载入口：

1. 校验模板路径和运行环境。
2. 在 `_LargeModelInference` 缓存中解包模板。
3. 加载模板指定的 Engine/ONNX 与 Bank；GPU 失败时沿用现有 CPU 回退规则。
4. 按模板输入尺寸创建三通道空图，执行一次 native 推理完成 CUDA/TensorRT 预热。
5. 全部成功后才替换当前检测器并释放旧检测器。

模板路径和文件最后写入时间未变化时跳过重复加载。阈值和最大框数不参与模型缓存匹配。

模型预加载发布和节点参数提交使用同一个配置门；流程运行也必须在该门内读取参数并进入推理。这样连续运行期间保存新模板时，运行线程不会把旧参数与新检测器组合，也不会把刚预热的新模型重新切回旧模型。

### 参数窗口

保存事件改为异步事件。参数校验成功后，保存按钮显示“模型加载中...”，同时禁用模板选择、刷新和保存操作；后台预加载成功后隐藏窗口，失败则恢复控件并显示错误。现有设计器控件足够，不新增运行时控件。

### 兼容与异常处理

- `Run` 仍保留一次兜底的 `EnsureModelLoaded`，用于旧方案恢复或未经过保存窗口的调用。
- 保存后的同模板运行采用纯内存快速匹配，不再每帧查询模板文件时间戳。
- 预热失败时销毁新检测器，不覆盖旧检测器。
- 现有 `_LargeModelPreview` 历史目录不自动删除，避免未经用户授权清理文件；新代码不再继续生成该缓存。

## 验证

- 自动化检查保存按钮必须等待节点预加载后才隐藏窗口。
- 自动化检查模板预览只调用清单读取，不调用完整解包。
- 自动化检查运行时缓存匹配不再依赖阈值。
- 执行大模型集成测试及解决方案编译。
