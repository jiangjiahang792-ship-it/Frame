# TDJS-Vision 启动动画设计

## 目标

软件启动后先显示独立的轻盈科技风格启动页，在后台完成主窗体、设备配置和方案数据加载。启动页持续显示当前加载阶段、当前对象名称和总进度；关键加载全部成功且启动页至少展示 2 秒后，关闭启动页并显示主页面。

## 已确认需求

- 视觉方向采用 A“轻盈科技”：浅色渐变背景、红蓝单眼机器人居中、下方显示加载信息和进度。
- 机器人素材参考用户提供的吉祥物图片重新生成，不直接裁剪原图。
- 动画包含机器人轻微上下浮动、眨眼和天线呼吸灯效果。
- 启动页显示阶段、当前对象名称、当前序号、总数和总进度，不显示完整磁盘路径。
- 主窗体界面资源、设备配置以及默认或命令行指定方案加载完成后即可显示主页面。
- C# 脚本引擎预热和自动运行任务在后台继续，不阻塞主页面显示。
- 加载很快时，启动页仍至少展示 2 秒。
- 关键加载失败时停留在启动页，显示简体中文错误，并提供“重试”和“退出软件”。
- 非关键后台任务失败只记录日志，不阻止进入主页面。
- 不引入新的第三方运行库。

## 技术方案

采用“独立启动页 UI 线程 + 主 UI 线程启动协调器”。启动页拥有独立的 STA 线程和消息循环，因此主线程执行现有同步窗体构造、设备反序列化或方案加载时，机器人动画和进度界面仍然保持响应。

主线程使用自定义 `ApplicationContext` 启动消息循环，但在初始化完成前不显示 `FormMain`。启动协调器在主 UI 线程依次执行初始化步骤，通过接口向启动页线程上报不可变进度对象。成功后等待最短展示时间，关闭启动页，再显示主窗体。

不采用单 UI 线程全异步重构，因为当前设备恢复链路和大量静态子窗体均为同步 WinForms 代码；一次性改造成全异步会显著扩大风险。不采用主窗体遮罩，因为同步初始化会冻结遮罩动画，而且主窗体会提前暴露。

## 组件设计

### 启动进度模型

`IStartupProgressReporter` 定义进度上报接口，启动流程只依赖接口，不依赖具体窗体。

`StartupProgressInfo` 保存阶段名称、当前对象名称、当前序号、总数和百分比。构造函数负责边界校正，避免负进度或超过 100%。

`StartupProgressContext` 使用 `AsyncLocal` 保存当前启动进度接口和关键失败集合。现有同步反序列化事件链可以在不修改事件签名的前提下上报设备及流程加载状态。作用域结束后立即清理，避免普通运行期操作误发到启动页。

### 启动页线程

`StartupSplashController` 负责创建和关闭启动页线程，实现 `IStartupProgressReporter`，并将跨线程进度更新安全投递到启动窗体。

`FormStartup` 是无边框、居中显示的 WinForms 窗体。所有可视控件均在 `FormStartup.Designer.cs` 中声明和加入控件树，包括机器人图片、标题、状态标签、详情标签、进度轨道、进度填充、错误面板、“重试”和“退出软件”按钮、动画定时器。

启动页使用定时器更新机器人浮动位置、眨眼遮罩和天线呼吸灯透明度。动画只改变少量控件位置和绘制状态，不做逐帧大图解码，避免影响启动效率。

### 主程序启动上下文

`StartupApplicationContext` 负责：

1. 启动独立启动页线程。
2. 在主 UI 线程构造 `FormMain`。
3. 调用主窗体可等待的启动初始化入口。
4. 处理关键失败后的“重试”或“退出软件”。
5. 满足最短 2 秒展示时间后关闭启动页并显示主窗体。
6. 主窗体关闭时退出应用消息循环。

`Program.RunApplication` 保留现有单实例、线程池、启动诊断和 HslCommunication 授权顺序，只把直接 `Application.Run(FormMain)` 改为运行 `StartupApplicationContext`。

### 主窗体初始化

`FormMain_Load` 中当前执行的启动逻辑拆入可重复保护的 `InitializeForStartupAsync` 方法。该方法按顺序上报：

1. 初始化主窗口布局。
2. 应用语言资源。
3. 初始化海康相机 SDK。
4. 绑定工具窗口、登录和快捷键事件。
5. 恢复登录权限状态。
6. 加载命令行指定方案；没有指定方案时按配置加载默认方案。
7. 启动非阻塞的脚本预热和自动运行后台任务。

初始化方法必须幂等。主窗体最终显示触发 `Load` 事件时不会重复初始化。

## 方案和设备加载进度

方案读取阶段上报“读取方案文件”和“解析方案配置”。设备恢复阶段由现有反序列化事件链上报当前对象：

- 光源设备；
- 相机和 3D 相机；
- PLC；
- Modbus；
- TCP；
- 串口；
- 流程及流程节点。

每个加载器先筛选本类型对象并计算总数，再在创建对象前上报“当前序号/总数”。没有对应对象时上报该阶段已完成，不制造虚假等待。

## 错误处理

启动关键步骤抛出的异常由 `StartupApplicationContext` 捕获，记录完整异常日志，并在启动页显示简化的中文错误。错误界面不显示敏感完整路径，只显示失败阶段和异常消息。

用户选择“重试”时，优先复用尚未公开的主窗体：结构初始化保持幂等，只重新执行可重试的数据加载阶段，避免重复订阅静态事件。仅当主窗体构造阶段尚未得到实例时才重新创建。选择“退出软件”时关闭启动页并退出消息循环。

设备加载器当前存在空 `catch`。本次只在启动作用域内收集异常并记录日志，保持既有反序列化完成事件继续传播；事件链结束后统一将收集到的关键异常交给启动上下文处理，避免链路中断后资源处于不可判断状态。

脚本预热和自动运行属于非阻塞后台任务。其异常写入日志，不切回启动页，也不关闭已经显示的主页面。

## 视觉资源

重新生成一张独立的红蓝单眼机器人 PNG，主体居中、浅色纯净背景、无文字和水印。最终素材保存到项目 `Resources` 目录并通过项目资源访问，运行时不依赖项目外部文件。

启动页控件文字全部使用简体中文。界面采用浅蓝白渐变、红色品牌强调色和蓝色进度色，保持与参考图的亲和科技感。

## 测试与验证

- 先新增启动流程回归测试并确认因功能缺失而失败。
- 测试项目文件包含启动窗体、设计器、进度接口、启动上下文和资源。
- 测试 `Program` 仍保持单实例和授权顺序，并改由 `StartupApplicationContext` 运行。
- 测试启动窗体控件全部位于 `.Designer.cs`，且关键文字为简体中文。
- 测试进度模型的 0%、中间值和 100% 边界。
- 测试主窗体初始化入口幂等，自动方案加载被等待，脚本预热不阻塞。
- 运行现有单实例和主窗体相关回归脚本。
- 使用 Visual Studio 2022 MSBuild 编译解决方案，要求 0 个编译错误。
- 启动实际程序进行人工检查：动画持续响应、显示真实加载项、最少停留 2 秒、加载完成后才显示主页面。

## 范围限制

- 不重构全部设备反序列化架构。
- 不修改方案文件格式。
- 不新增取消启动功能，错误状态只提供“重试”和“退出软件”。
- 不让启动页阻塞脚本预热或方案自动运行的长期任务。
