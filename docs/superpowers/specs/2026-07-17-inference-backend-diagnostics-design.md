# AI 推理后端与分段耗时诊断设计

## 目标

让客户机日志明确显示无监督和大模型实际使用的推理设备、模型文件、输入尺寸及各阶段耗时，同时保证用户明确选择 GPU 时不会静默改用 CPU。

## 后端策略

- 无监督界面的 `GPU` 对应 DLL Demo 使用的 `GPU_ORT`，`AUTO` 对应 `AUTO_ORT`；已经写入模板的 `GPU_ORT`、`GPU_TENSORRT`、`AUTO_ORT` 和 `AUTO_TENSORRT` 保持原值。
- 无监督明确选择 GPU 时初始化失败直接报告错误；只有 AUTO 后端允许回退 CPU。
- 大模型设备模式为 GPU 时 Engine 初始化失败直接报告错误；只有 AUTO 模式允许回退 CPU ONNX。

## 诊断日志

- 模型加载成功时记录实际设备和实际模型完整路径。
- 每次节点成功日志记录输入尺寸、实际设备、图像准备、native 推理和结果处理耗时。
- native 耗时只覆盖 P/Invoke 的 `Infer` 调用；BGR 转换或复制归入图像准备，矩形转换与坐标映射归入结果处理。
- 节点原有总耗时保留，用于计算流程框架及日志发布等剩余开销。

## 范围

本轮只修正后端选择与增加证据日志，不删除图像复制。客户机返回新日志后，再依据分段耗时决定是否优化图像传递。

## 验证

- 新增回归测试覆盖 GPU_ORT 映射、显式 GPU 禁止 CPU 回退、实际后端状态和分段耗时字段。
- 运行无监督、大模型既有专项检查，并编译 `Debug|x64` 与 `Release|x64`。
