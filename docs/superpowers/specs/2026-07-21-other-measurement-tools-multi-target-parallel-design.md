# 其余测量工具多目标受限并发设计

## 1. 背景与目标

卡尺找圆已经采用“单次获取灰度图、多个位置修正目标受限并发、全部完成后按原顺序统一输出”的运行模式。实际程序日志显示，5 个目标的卡尺找圆节点墙钟耗时中位数由 33ms 降至 9ms，因此将相同模式扩展到其余支持位置修正列表的测量工具。

本次目标是在不改变节点参数、结果结构、绘制方式和失败语义的前提下，缩短多目标测量的实际墙钟耗时。单目标继续走原直接执行路径，不承担并发调度成本。

## 2. 实施范围

以下 7 个测量工具纳入本次改动：

1. 卡尺找线；
2. 卡尺找椭圆；
3. 找点；
4. 线线夹角；
5. 点点距离；
6. 点线距离；
7. 点区域距离。

卡尺找圆已经完成并发化，本次只作为参考实现和回归对象，不重复改造。

## 3. 方案选择

采用“各工具显式调用公共并发执行器”的方案。每个工具的 `ExecuteMeasures` 明确调用 `MultiTargetMeasurementRunner.RunParallel`，公共执行器只负责并发调度、顺序保持、取消传播和异常隔离。

不把原有 `Run` 方法暗中改成并发，避免其他调用者在不知情时改变执行语义；也不只改三个直接图像测量工具，因为四个组合测量工具的绘制模式内部同样会执行卡尺算法，多目标时具有实际并发收益。

## 4. 公共并发上限

`MultiTargetMeasurementRunner` 首次加载时通过 `Environment.ProcessorCount` 读取操作系统报告的 CPU 逻辑处理器数量并缓存自动并发上限：

```text
自动并发上限 = max(1, CPU 逻辑处理器数量 - 1)
实际并发度 = min(目标数量, 自动并发上限)
```

当前开发机读取到 24 个逻辑处理器，因此缓存的自动并发上限为 23。保留一个逻辑处理器是为了给界面、相机回调和其他流程留出运行余量。

当目标数量小于等于 1，或实际并发度小于等于 1 时，公共执行器调用原串行入口，并在调用线程上直接完成测量。

## 5. 数据流设计

### 5.1 图像测量工具

卡尺找线、卡尺找椭圆和找点按以下顺序运行：

1. 在进入并发区之前读取位置修正列表；
2. 没有目标时直接返回空结果；
3. 获取一次灰度图；
4. 每个并发目标独立创建仿射变换后的运行参数；
5. 所有目标只读共享同一张灰度图；
6. 每个目标只创建和修改自己的算法参数、临时图像及结果对象；
7. 全部目标结束后，按位置修正输入顺序统一返回；
8. 所有并发工作结束后才释放由当前节点临时创建的灰度图。

### 5.2 组合测量工具

线线夹角、点点距离、点线距离和点区域距离保留现有两种数据源行为：

- 订阅模式不展开位置修正列表，只有一个恒等目标，继续走单目标直接执行路径；
- 绘制模式启用位置修正时展开多个目标，并发执行各目标的参数变换、卡尺算法和几何计算；
- 绘制模式只获取一次灰度图，全部目标只读共享；
- 每个目标的测量结果、边缘点列表和几何结果均为独立对象，不跨目标写共享集合。

## 6. 线程安全

`Mat` 在并发区中只作为算法输入，任何需要模糊、边缘、掩膜或轮廓处理的步骤都创建目标自己的局部 `Mat`。调用方在全部目标完成前不会释放共享灰度图。

位置修正变换服务只读取输入参数并返回新的点或点集，不维护可变共享状态。公共执行器使用固定结果数组，每个目标只写自己的下标，最终输出顺序不会受完成先后影响。

找点工具当前在目标委托中执行 `LastTimingInfo.RuntimeParamMs += ...`。该写法在并发后存在竞争，本次改为使用局部 `long` 累加计时 Tick，并通过 `Interlocked.Add` 汇总；并发结束后再一次性换算为毫秒写入 `LastTimingInfo`。其他统计字段从最终结果集合统一求和，不在并发区写共享对象。

## 7. 失败、取消和结果语义

- 单个目标发生普通异常时，公共执行器在原位置生成该工具现有的全零 NG 项；
- 某个目标失败不阻止其他目标继续运行；
- 任一目标失败时，节点总体状态保持 NG；
- 取消异常不转换成失败项，继续向节点运行层传播；
- 结果数量和顺序始终与位置修正列表一致；
- 汇总 `AlgorithmMs` 继续表示各目标算法耗时之和，它是累计工作量，不等于并发后的节点墙钟耗时。

## 8. 节点计时与日志

7 个节点的运行入口统一使用 `Stopwatch`，并把同一个计时器传给所有成功、取消和失败状态的 `SetRunResult`。日志中的节点耗时表示调用方实际等待的墙钟时间，作为改动前后性能对比的主要指标。

不在本次新增逐目标常规日志，避免生产运行时增加磁盘写入和字符串格式化开销。需要分析时使用现有节点完成日志和结果中的逐目标 `AlgorithmMs`。

## 9. 测试策略

测试按测试驱动方式实施，至少覆盖：

1. 7 个工具都显式调用 `RunParallel`，且工具内部不重复实现 `Parallel.For`；
2. 图像测量工具和组合工具绘制模式均只获取一次灰度图；
3. 找点计时采用线程安全累加，并在并发结束后统一写入；
4. 7 个节点均使用 `Stopwatch` 报告墙钟耗时；
5. 公共执行器继续满足真实并发重叠、最大并发度、单目标同线程、固定顺序、失败隔离和取消传播；
6. 现有多目标位置修正、卡尺、找点和几何测量专项回归全部通过；
7. `Debug|x64` 完整编译通过；
8. 用户使用正式方案运行后，从日志分别比较 1、3、5 目标的节点中位数和尾部耗时。

## 10. 验收标准

- 7 个工具的多目标绘制模式均由公共执行器受限并发；
- 单目标行为、订阅模式、结果字段、目标顺序和 NG 规则保持兼容；
- 同一节点每轮最多获取一次共享灰度图；
- 并发区不存在对共享可变结果或计时 `double` 的非线程安全写入；
- 所有专项测试和完整编译通过；
- 代码注释明确逻辑处理器缓存、共享只读输入、并发结果顺序及找点计时汇总思路。

## 11. 非目标

本次不修改模板匹配、位置修正和相机触发流程，不增加新的界面控件，不改变方案数据结构，也不把不同流程或不同节点强制并发运行。跨流程 CPU 资源调度如需进一步限制，应在取得多流程现场日志后另行设计。
