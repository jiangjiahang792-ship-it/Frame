# 复合测量双采样模式与多目标串行统一设计

## 目标

在不改变位置修正、ROI 仿射、结果顺序和失败占位语义的前提下，把复合测量工具的卡尺采样能力补齐，并把全部测量工具的多个模板目标统一为串行执行。

## 已确认范围

- 卡尺找线、卡尺找圆、卡尺找椭圆的多个模板目标统一使用串行执行。
- 卡尺找圆从 `MultiTargetMeasurementRunner.RunParallel` 改回 `Run`。
- 线线夹角、点点距离、点线距离、点区域距离继续保持现有串行执行，不引入受限并发。
- 公共 `RunParallel` 执行器和相关通用测试暂时保留，但本次范围内的业务测量工具不再调用它。
- 找点使用独立算法，不使用公共卡尺灰度剖面，因此本次不增加卡尺采样模式。

## 采样模式设计

公共枚举继续复用 `CaliperSamplingMode`：

- `Fast = 0`：中心线单像素最近邻采样，优先保证速度。
- `AntiInterference = 1`：沿卡尺宽度多点双线性采样并求平均，优先保证抗干扰能力。
- 旧方案缺少新增字段时依靠枚举零值和属性初始化进入快速采样。
- 未知枚举值由公共算法和界面加载逻辑回落到快速采样。

四种复合测量工具的保存粒度如下：

| 工具 | 采样模式保存方式 |
| --- | --- |
| 线线夹角 | 直线1、直线2分别保存 |
| 点点距离 | 点1圆卡尺、点2圆卡尺分别保存 |
| 点线距离 | 点圆卡尺、直线卡尺分别保存 |
| 点区域距离 | 点圆卡尺保存一个模式；区域几何计算不使用卡尺采样 |

## 界面设计

- 每个复合测量窗体只增加一组“采样模式”下拉框，选项为“快速采样”和“抗干扰采样”。
- 对于包含两套卡尺的工具，下拉框跟随现有“运行ROI”选择器：切换 ROI 前保存当前模式，切换后加载对应卡尺的模式。
- 两套卡尺的模式在参数中独立保存，界面只显示当前正在编辑的那一套，避免增加两组重复控件。
- 点区域距离只有一套点圆卡尺，直接保存和加载单个模式。
- 所有新增 WinForms 控件均声明和布局在对应 `.Designer.cs` 中，显示文本使用简体中文。

## 参数与运行数据流

1. 节点参数以 `CaliperSamplingMode.Fast` 作为新增属性默认值。
2. 包含两套卡尺的窗体把模式保存在各自的 `RoiRunSettings` 中。
3. `SetParam2Form` 把节点参数加载到运行 ROI 缓存，再加载当前 ROI 的下拉框。
4. 切换运行 ROI 或保存节点时，先把下拉框值写回当前 ROI 缓存。
5. 位置修正构造运行时参数时原样复制采样模式，不参与缩放或旋转。
6. `BuildLineParams` 或 `BuildCircleParams` 把对应模式传给公共卡尺算法。
7. 公共算法只有明确选择 `AntiInterference` 才执行高成本采样，其他值均进入快速采样。

## 串行执行设计

- 所有测量节点统一调用 `MultiTargetMeasurementRunner.Run`。
- 输入包含多个位置修正目标时，严格按照目标列表顺序逐个完成测量。
- 单目标失败继续生成同序号全零 NG 项，后续目标继续执行。
- 取消异常继续立即向上抛出。
- 输出数量、目标序号、绘制顺序和总体 OK/NG 判断保持不变。
- 单个目标内部的卡尺扫描点继续由公共算法串行处理，不增加任务调度。

## 兼容和验证

- 新增失败优先的源码契约测试，覆盖参数默认值、独立保存、ROI 切换缓存、运行时复制、算法传递和 Designer 控件。
- 更新卡尺多目标测试，要求卡尺找圆使用串行 `Run`，并检查全部测量工具不存在业务层 `RunParallel` 调用。
- 使用旧方案或缺少新增字段的 JSON 验证所有新增模式均为快速采样。
- 运行双采样、位置修正和多目标测量相关专项回归。
- 执行 `Debug|x64` 非增量构建，要求 0 个错误；既有警告如实记录。

## 不在本次范围

- 不删除公共受限并发执行器。
- 不增加新的线程池、任务调度器或并发配置。
- 不修改找点算法的采样方式。
- 不调整模板匹配、位置修正和相机触发流程。
