# 卡尺找圆多目标并发设计

## 1. 背景

卡尺找圆已经支持根据位置修正列表对多个模板目标执行测量，但当前公共执行器使用普通 `for` 循环逐目标串行运行。用户实测单目标找圆耗时低于 1ms，而 5 个目标的节点耗时约为 33ms，希望多个目标共享同一张灰度图并发运行算法，最后统一输出结果。

当前实现已经具备并发所需的基础条件：

- `ExecuteMeasures` 在进入目标循环前只获取一次灰度图；
- 灰度图在卡尺算法中只读取，不写入；
- 每个目标都会创建独立的运行参数、边缘点集合和拟合临时对象；
- 多目标结果通过目标序号和列表位置保持稳定顺序；
- 单目标异常已经能够转换为对应位置的全零 NG 结果。

## 2. 目标

- 多个位置修正目标共用同一张只读灰度图，并发执行各自的卡尺找圆算法。
- 单目标继续使用直接执行路径，不引入并发调度开销。
- 并发完成后按位置修正列表原始顺序统一输出，不能按任务完成顺序输出。
- 单个目标失败时保留同序号全零 NG 结果，其他目标继续执行。
- 流程取消时停止调度后续工作并向上层传播取消状态。
- 限制并发度，避免多流程同时运行时过度占用线程池和 CPU。
- 公共执行器提供可复用能力，但本次只将卡尺找圆切换到并发路径。

## 3. 非目标

- 不并发单个目标内部的卡尺扫描循环，避免细粒度任务和嵌套并发开销。
- 不修改卡尺找圆的边缘提取、平滑、极性选择和圆拟合算法。
- 不改变 ROI 绘制、位置修正仿射规则、数值舍入或总体 OK/NG 判定规则。
- 不在本次同时改造找线、找椭圆、找点和几何测量工具。
- 不增加 WinForms 控件或方案参数，不需要修改任何 `.Designer.cs` 文件。

## 4. 方案对比与决策

### 4.1 目标级同步并发

在公共多目标执行器中增加目标级并发入口，使用受限并发循环同步等待全部目标结束。每个工作单元完整执行一个目标的参数变换和找圆算法。

优点：任务粒度合适；改动集中；现有节点仍然同步完成；容易保持顺序、失败隔离和取消语义。

缺点：多流程同时运行时可能竞争 CPU，因此必须设置最大并发度。

### 4.2 `Task.WhenAll` 异步化

为每个目标创建任务并等待全部任务完成。

优点：异步组合表达清晰。

缺点：需要继续改造节点 `Run` 和 WinForms 预览事件的异步调用链；对当前纯 CPU 计算没有额外收益，并会扩大改动范围。

### 4.3 单目标内部卡尺并发

把每个圆内部的多条卡尺扫描拆成并发任务。

优点：单目标也可能利用多核。

缺点：单条卡尺工作量较小，线程调度、数组分配和结果合并成本可能超过计算成本；多个目标时还会形成嵌套并发。

### 4.4 决策

采用方案 4.1。并发粒度限定为“一个模板目标的一次完整找圆”，不异步化节点调用链，也不并发圆内部卡尺。

## 5. 架构与接口

### 5.1 公共执行器

在 `MultiTargetMeasurementRunner` 中保留现有串行 `Run` 方法，并新增目标级并发方法。并发方法继续接收：

- 按模板目标顺序排列的位置修正集合；
- 流程取消令牌；
- 单目标执行委托；
- 单目标失败结果工厂。

并发方法内部使用固定长度结果数组，每个目标只能写入自己的数组下标。全部目标结束后一次性转换为列表，因此输出数量和顺序始终与输入修正集合一致。

### 5.2 并发度

默认最大并发度计算规则为：

```text
min(目标数量, max(1, CPU逻辑核心数 - 1))
```

目标数量为 1 时直接复用串行执行路径，不创建并发循环。目标数量大于 1 时才启用受限并发。

并发方法允许由测试传入明确的最大并发度，以便稳定验证并发上限和单目标快路径；生产调用使用自动计算值。

### 5.3 卡尺找圆接入

`NodeParamFormCaliperCircle.ExecuteMeasures` 的数据流调整为：

```text
读取位置修正列表
  → 获取一次只读灰度图
  → 并发执行每个目标的 BuildRuntimeParam + ExecuteOne
  → 等待全部目标完成
  → 按原顺序返回结果列表
  → 节点统一构建汇总结果与绘制结果
```

灰度图的生命周期覆盖完整并发区间，并在所有目标结束后才根据原有所有权规则释放。并发工作单元不得释放、替换或修改共享灰度图。

## 6. 线程安全

- `Mat gray` 只用于像素读取，所有工作单元共享同一个实例，不执行颜色转换、绘制或释放。
- `BuildRuntimeParam` 为每个目标创建独立参数对象。
- `CaliperMeasurementAlgorithm.FindCircle` 的剖面数组、梯度数组、边缘点集合和拟合 `Mat` 均为方法局部对象。
- 每个工作单元只写入结果数组的唯一位置，不共享可变结果集合。
- 汇总状态、绘制圆和文字只在并发结束后由调用线程构建。
- 不在并发工作单元中更新 WinForms 控件或写入节点公共 `Result`。

## 7. 异常与取消

- 普通单目标异常由该目标的失败工厂转换为全零 NG 项，并写回原目标下标。
- 一个目标失败不会取消其他目标。
- `OperationCanceledException` 不得转换为失败项，必须传播到节点运行层。
- 并发循环绑定流程取消令牌；取消发生后不再开始尚未执行的目标，并等待已经进入算法的工作单元安全退出。
- 由于当前找圆算法内部没有取消检查，已开始的单次找圆会执行完毕后再结束；本次不把取消检查插入像素级循环，以免影响热路径性能。

## 8. 计时语义

- 节点 `RunTime` 表示从节点开始运行到全部目标汇总完成的墙钟耗时。
- 节点运行计时改用已有的高精度 `Stopwatch` 重载，避免亚毫秒算法被 `DateTime.Now` 精度干扰。
- 每个目标的 `AlgorithmMs` 仍表示该目标找圆算法自身耗时。
- 汇总 `AlgorithmMs` 继续表示各目标算法耗时之和；并发后它代表累计 CPU 工作量，可能大于节点墙钟耗时，这是预期语义。

## 9. 测试设计

### 9.1 公共执行器行为测试

- 单目标只执行一次并返回同一位置，不进入并发调度。
- 多目标工作单元能够发生执行重叠，而不是继续串行。
- 并发度不超过指定上限。
- 目标完成顺序被故意打乱时，最终结果仍按输入顺序排列。
- 中间目标抛出普通异常时，只生成该位置失败项，其他目标正常完成。
- 取消令牌触发时向上抛出取消异常，不生成伪失败结果。

### 9.2 卡尺找圆接入测试

- `ExecuteMeasures` 只在并发循环外获取一次灰度图。
- 卡尺找圆调用公共并发入口，不继续调用串行入口。
- 单目标仍走公共执行器的直接执行快路径。
- 汇总结果数量、目标序号、全零失败项和总体 NG 规则保持不变。

### 9.3 性能验证

使用用户方案和相同图像、相同卡尺参数进行对比：

- 预热后分别采集单目标与 5 目标连续运行数据；
- 同时记录节点 `RunTime`、汇总 `AlgorithmMs` 和每目标 `AlgorithmMs`；
- 对比改造前后 5 目标墙钟耗时的中位数，确认并发产生实际收益；
- 确认单目标快路径没有出现可观察的性能回退。

性能结果受 CPU 核心数和同时运行流程数量影响，因此自动化测试验证并发行为，不使用固定毫秒阈值作为构建门禁。

## 10. 验收标准

- 5 个目标只读取一次灰度图，并发执行 5 次独立找圆。
- 多核机器上的最大同时执行目标数符合并发度上限。
- 单目标保持直接执行路径。
- 输出顺序、失败全零、总体 NG 和取消行为全部通过自动化测试。
- 卡尺找圆专项测试、多目标公共执行器测试及 `Debug|x64` 完整编译通过。
- 使用用户方案完成改造前后性能记录，并报告实际结果，不以理论倍数替代实测。
