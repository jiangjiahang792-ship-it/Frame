# 组合模块顶部折叠导航实现计划

## 目标与设计
用户要求直接参照 VM 操作改进现有流程编辑器。已实机验证：顶部下拉显示流程及缩进组合模块，点箭头只折叠/展开且不关闭列表，点名称进入画布；组合模块配置有输入、输出页，包含名称、类型和订阅关系。
按用户“直接改”的约定执行，不额外要求计划批准。在现有工作目录增量修改，保留其他未提交工作，不自动提交。

## 实现任务
- [x] 顶部固定“流程导航”入口，弹出可滚动折叠树；流程多时入口始终可见。按稳定流程 ID 和组合节点 ID 路径定位，不按名称解析。折叠不跳转，名称点击跳转并收起；保留折叠状态。
- [x] 同一编辑面板支持进入内部及返回父级，显示完整路径，新增控件全部在 Designer 文件。双击组合节点进入内部，参数设置独立按钮，输入/输出按钮直达端口配置。
- [x] 组合节点提供 GetEditableProcess()、SaveEditableProcess()、ConfigurePorts(bool output, IWin32Window owner) 接口。内部编辑不注册顶层流程；保存递归刷新快照并保留外部绑定。运行使用同一内部对象，避免编辑页面指向已释放对象。
- [x] 组合模块可以单独运行，沿用取消与外部运行会话互斥；输入使用外部订阅/常量，输出保留布尔、图像及自动原始类型，外部可订阅。禁止运行中编辑。
- [x] 实际程序集测试覆盖进入/返回、深层保存、旧快照兼容、展开折叠、多个重名模块、单独运行与类型输出，完成 Release 构建和真实界面检查。

## 文件边界
- 主任务：Forms/ProcessNew/FormNewProcessWizard*、ProcessEditPanel*、ProcessFlowCanvas.cs、ConfigHelper.cs、项目文件与导航测试。
- 并行端口任务：Node/6-LogicTool/CompositeModule/*，组合模块编辑运行接口与端口测试；不修改主任务文件。

## 核心验证
真实窗体和真实组合节点组成测试，无现场设备：断言组合内布尔、图像、对象输出不丢类型；编辑后 JSON 保存/恢复保留端口和节点；重复开关导航不增加顶层流程；运行期间不替换内部流程；重名按 ID 跳转。
构建命令：MSBuild TDJS-Vision.csproj /p:Configuration=Release /p:Platform=x64 /p:OutputPath=bin/CompositeNavigationValidation/。
测试命令：Tests/CompositeNavigation.Tests.ps1 和 Tests/CompositeEditing.Tests.ps1，指定独立构建目录；最后运行关联既有回归。

## 审查重点
1. 内部 ID 与顶层节点重复，不得串订阅或跳错流程。
2. 多层内部编辑保存必须由内向外且不丢外部输入绑定。
3. 参数窗口修改后内部运行缓存必须刷新且画布不得引用已释放节点。
4. 图像寿命与运行成功标记不能被单独运行破坏。
5. 折叠树打开不应实例化所有内部流程，避免大量流程时卡顿。
