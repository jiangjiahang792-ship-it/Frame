# 运行界面日志框实施记录

用户已在对话确认功能设计；沿用当前“增加界面设计器”分支和未提交的设计器代码，不创建丢失当前修改的新工作区。

## 范围

新增日志框，订阅全部或指定根流程，自动包含嵌套组合模块。日志列为时间、等级、来源、内容；有清空、暂停刷新、自动滚动和最低等级过滤。默认保留 2000 条，可配置上限。配置参与复制、撤销、方案保存和模板导入导出，日志正文仅内存。文件日志和系统日志开关保持原状。

## 接口与任务

1. 日志生产侧：AsyncLocal 作用域携带根流程实例及嵌套节点路径；在入队前捕获不可变记录。独立有界订阅者，按实例过滤，批量获取，异常不反向影响运行。组合模块不能按编号或名称误归属。
2. 纯 UI 契约 RuntimeLog.cs：RuntimeLogLevel、RuntimeLogEntry、IRuntimeLogSource.Subscribe(int? processId, int capacity)、IRuntimeLogSubscription.Drain(int maxCount)/Clear()/Dispose()。正式适配 RuntimeFrameworkLogSource 接收根流程实例快照；设计预览仅模拟数据。
3. RuntimeLogWidget 与 Designer：虚拟列表、有界展示、工具按钮、中文提示、按批刷新、不重复设置 tooltip；不直接引用生产对象。
4. 布局添加 Log 类型、LogProcessId/LogCapacity/LogMinimumLevel/LogAutoScroll，校验范围 100..10000；工具箱、属性区、静态绘制器、预览原生控件和宿主一并接通。
5. 验证：先失败的模型及 UI 测试；并发上下文、深层组合模块归属、指定流程隔离、队列上限、清空/暂停/关闭、布局序列化和旧组件回归。正式 Release x64 编译到独立目录，不启动生产主程序。

## 分工边界

日志后端只改 Logger、Process 的日志作用域、必要的组合模块上下文与自己的后端测试；UI 控件任务只改新 RuntimeLogWidget 两个文件及自己的控件测试；主任务维护 RuntimeLog 契约、布局/编辑器/预览/宿主/项目注册，统一集成。任务之间仅共享上述接口，禁止重复写同一文件。
