# 结果发送节点

入口为“结果处理 → 结果发送”。一个节点使用一个已添加的 PLC 或 Modbus 主站，发送列表中的各行按顺序写入该设备；向不同设备发送时添加多个节点。

## 配置

1. 将结果来源节点连接到结果发送节点的上游，选择通信设备。
2. 在右侧“上游节点结果”树选择具体字段，点击“添加”或“订阅到当前行”。
3. 选择发送行，在下方设置目标地址、取值方式和写入类型。
4. 保存参数后运行方案。“预览发送值”只读取最近一次结果，不发送设备指令。

支持四则运算的计算结果和命名变量、AI 检测项的检测值与判定、测量模块的标量及多目标明细、多条件判定的条件结果，也支持统一订阅目录中其他已公开的基础值。

AI 检测项在订阅树、发送列表和参数框中使用软件现有的中文名称显示，内部保留稳定键以便恢复方案。目录直接读取方案配置，软件重新打开后无需先运行；已启用和未启用的检测项均展开为明细检测值、明细判定、检测项判定三个入口。固定模式读取所选检测配置；通信切换模式合并默认模板、当前配置和已配置的切换模板，同名检测项去重。没有关联检测配置和运行结果时，可选择“指定检测项”，再填写中文名称。

参数页只显示当前取值方式和写入类型适用的选项。结果直接转换到写入类型，不再提供值处理、倍率、偏移或真假映射；旧方案中的这些设置也不再生效。

## 类型与取值

写入类型包含 `bool`、`int`、`uint`、`ushort`、`short`、`string`、`double`、`float`。类型转换拒绝溢出、NaN、无穷大和小数直接转整数；需要取整时先在四则运算节点中处理。布尔转换只接受 true、false、真、假、0、1。

- 直接取值：发送一个值；存在多个值时需选择其他取值方式。
- 指定第几项：序号从 1 开始，顺序沿用上游集合。
- 全部连续发送：配置容量、数量地址和剩余位置是否补默认值。数量地址写入 `ushort`，数据发送完成后再写数量。超出容量时拒绝发送。
- 汇总为单值：最大值、最小值、平均值、求和、全部为真或任意为真。汇总已有值，没有值时发送默认值。

本轮未检出对应检测项、检测明细为空、明细检测值为空、指定序号不存在或目标未测得结果时，固定按写入类型发送默认值：所有数值类型为 `0`，`bool` 为 `true`，`string` 为“无效”。已经检测出的 `false` 和其他有效值保留原值。

连续发送保留明细位置，空项使用默认值；开启“剩余位置补默认值”时填满预留容量。零目标时数量写 `0`，即使关闭补默认值，也至少在起始数据位置写入一个默认值。默认占位不增加目标数量。

字符串默认使用 UTF-8，每个元素占用固定的偶数字节容量，剩余字节补零；过长或无法编码的字符拒绝发送。“无效”需要 UTF-8 至少6字节，或 GB18030 至少4字节；ASCII 无法表示中文默认值。PLC 使用编码后的原始字节写入，Modbus 将前一个字节放在寄存器高八位、后一个字节放在低八位。字符串数组按固定字节容量连续排列。

## 执行约定

- 到达节点后读取本轮已成功执行的上游结果，完成全部行的转换与基础预检，直接发送。发送快照不受后续参数或结果变化影响。
- 默认值仅处理缺少结果值的情况；上游未成功执行、订阅节点被删除、连线断开、非法转换及设备通信失败仍返回错误。
- PLC 和 Modbus 两种设备均不参与工件有序排队，不申请有序端点租约，不新增发送锁。只保持单次调用内的行顺序，不保证不同工件、流程或节点的发送先后；多个调用可能交错写入同一设备。底层通信库已有的连接同步机制保留。独立的 PLC 写入、相机 IO 和串口发送也采用直接发送。
- Modbus 数值保持现有设备字序，长数组按协议报文容量分批发送；PLC 数值使用各设备客户端的原生类型写入。
- 已知 Modbus 及常用 D、DM、DT 地址的数据区和数量区会检查范围重叠；其他 PLC 地址格式由具体设备协议处理。
- 每行先写数据，再写数量。某行失败后停止后续行，已写入内容不回滚，不自动重试。接收端如需整批一致性，需先通过独立地址区或业务协调避免多个调用交错覆盖，再使用完成信号和接收端握手；数量本身不是整批完成握手，单独增加完成信号也不能消除并发覆盖。
- 发送开始前可以取消；整批发送开始后等待实际写入完成或失败，不中途撤销已发送指令。全部行写入成功后才报告节点成功，这不等于 PLC 业务程序已经处理或执行。

节点输出“发送成功、成功条数、失败行、错误信息”。成功条数表示数据及对应数量均完成的行数，失败行从 1 开始。

## 实现与验证

控件声明及布局位于 `ParamFormResultSend.Designer.cs`，通过取值解析、类型转换、设备写入接口分离职责。PLC 额外类型通过可选的 `IResultSendTypedPlc` 能力接口扩展，现有 `IPlc` 插件无需被迫修改。

专项脚本：`Tests/ResultSend.Tests.ps1`，默认使用 `bin/ResultSendValidation` 中的独立构建程序集。测试仅连接本机随机端口模拟服务，未连接现场设备。
